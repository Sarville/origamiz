# 2026-09-10 — VK Mini App port

## Задача

Портировать Origamiz в VK (Mini App), взяв за образец уже работающий VK-порт
Colorit (`../flowit`, тот же аккаунт, задеплоен на `server-games`) — платежи,
синхронизация/облако, реклама, бэкенд для покупок, защита от запуска вне ВК.
Задеплоить рядом с Colorit на том же сервере, не мешая ему.

## Что сделано

**Клиент** (`src/js/platform/vk_wrapper.js`, новый файл):
- `PlatformWrapperImplVk extends PlatformWrapperImplBrowser`, аналог
  `yandex_wrapper.js`. Использует `@vkontakte/vk-bridge` (тот же пакет и
  версия, что у Colorit).
- Определение среды — `vk_user_id` в query (как в Colorit's `vkSdk.ts`).
- Реклама: `VKWebAppCheckNativeAds`/`VKWebAppShowNativeAds` с
  `ad_format: 'reward'|'interstitial'`; постоянный баннер —
  `VKWebAppShowBannerAd`/`HideBannerAd`.
- Облачные данные (`getCloudData`/`setCloudData`): в отличие от Yandex (один
  блоб через `player.setData`) и от Colorit (по одному ключу на уровень),
  здесь **каждый верхнеуровневый ключ** (`wallet`, `unlocked`,
  `blueprintLibrary`) — своя запись VK Storage, с ручным чанкингом по
  ~3800 байт под ключевой лимит VK в 4096 байт (Colorit словил именно эту
  проблему в проде — см. его `docs/vk-gotchas.md`). `blueprintLibrary` может
  доходить до ~150 КБ → десятки чанков, но это нечастая операция (сохранение
  чертежа), не проблема для лимита VK на количество ключей.
- Покупки: `VKWebAppShowOrderBox({type:'item', item})`, проверка
  `result.success` (не `result.status` — тип в `@vkontakte/vk-bridge`
  формально неверный, это тоже задокументировано в находках Colorit).
  У VK **нет** клиентского API "список моих покупок" (в отличие от Yandex) —
  источник истины для `disable_ads`/`currency_pack_10k` — свой бэкенд
  (см. ниже), клиент запрашивает его при старте и после покупки.
  `purchaseCurrencyPack()` после успешного order box дожидается (короткий
  poll, до 5 попыток раз в секунду) появления заказа в `pendingCurrencyPacks`
  от вебхука и только тогда начисляет и "потребляет" его — специально
  сделано так, чтобы начисление происходило **только** в одном месте
  (`creditAndConsumeCurrencyPack`), иначе optimistic-клиентское начисление и
  серверный вебхук могли бы задвоить начисление валюты.

**Бэкенд** (`ops/vk-payments/server.js`, новый, отдельный от Colorit'овского):
- Тот же алгоритм подписи (launch-params HMAC-SHA256, платёжный md5-sig),
  тот же `_test`-суффикс webhook, тот же Referer-softcheck — скопировано с
  Colorit.
- Плюс то, чего у Colorit не было: персистентный "гроссбух" покупок по
  `vk_user_id` (`/data/entitlements.json`, том в контейнере) — потому что у
  Origamiz два товара с состоянием (`disable_ads` разовый,
  `currency_pack_10k` повторяемый), а не один разовый донат. Новые эндпоинты
  `GET /vk/origamiz-entitlements` и `POST /vk/origamiz-consume`, которые
  дергает клиент.
- Самопроверка: `ops/vk-payments/server.test.js` (без фреймворка, `assert` +
  реальный HTTP-запрос к поднятому серверу) — гейт входа, вебхук, ледгер,
  consume. Прогоняется через `node ops/vk-payments/server.test.js`.
- **Цена товаров — не подтверждена.** VK берёт оплату в «голосах», официального
  курса голос→рубль для разработчиков не нашлось (розничная цена голоса
  колеблется ~7–11 ₽ в зависимости от способа покупки); подставлены
  `disable_ads: 21`, `currency_pack_10k: 15` как грубая оценка соответствия
  150₽/100₽ (ценам в Yandex-сборке). **Нужно перепроверить по факту первой
  тестовой покупки в кабинете платежей VK** и поправить `ITEMS` в
  `ops/vk-payments/server.js`, если сумма спишется не та.

**Билд**: новый вариант `vk` в `gulp/build_variants.js` (аналог `yandex`, но
без отдельного тега `<script>` — vk-bridge просто бандлится), `G_IS_VK`
define в `gulp/js.js`, `npm run build-vk`/`serve-vk`. `application.js` и
`states/ingame.js` (пауза при потере фокуса, как у Yandex — античит для
валюты) обновлены на `G_IS_VK`.

**Деплой** (`ops/README.md`, новый — с явным предупреждением, что
`Caddyfile` общий с Colorit и его нельзя просто перезаписывать):
- Новый контейнер `vk-payments-origamiz` (сеть `games-net`, том
  `/opt/games/vk-payments-origamiz/data` для `entitlements.json`,
  `VK_APP_SECRET` в окружении контейнера — **не** в репозитории).
- `Caddyfile` расширен (не переписан): добавлен `@vkOrigamizEntry`
  forward_auth-гейт и три `handle /vk/origamiz-*` блока; существующие
  `@soundsDirect`/`@static` regex расширены (`(res/)?sounds/`), чтобы
  накрыть путь Origamiz (`res/sounds/...`) — Colorit не тронут и
  регресс-проверен (403 без launch-параметров по-прежнему).
  **Важно**: кэш `immutable, max-age=31536000` **намеренно не** применён к
  JS Origamiz (`bundle.js`/`*.bundle.js`) — в отличие от Next.js-сборки
  Colorit, эти файлы не хэшируются по содержимому
  (`gulp/rspack.production.config.js`), вечное кэширование держало бы
  устаревший билд после каждого деплоя.
- Собрано (`npm run build-vk`) и синхронизировано
  (`rsync -az --delete build/ server-games:/opt/games/site/vk/origamiz/`).
- Живая проверка: гейт входа 403 без валидной подписи / 200 с валидной,
  entitlements/consume работают, звук отдаёт 403 без Referer и 200 с ним
  (то же поведение, что и у Colorit — проверено на его собственном файле),
  Caddy `caddy validate` пройден перед заменой конфига.

## Осталось сделать (не может сделать Claude — нужен доступ к аккаунту VK)

1. В кабинете приложения VK (App ID `54764973`) указать адрес запуска
   Mini App: `https://games.sarville.online/vk/origamiz/`.
2. В разделе «Платежи» этого приложения указать callback-адрес:
   `https://games.sarville.online/vk/origamiz-payments`, и убедиться, что
   приём платежей включён (юрлицо/самозанятость — если уже настроено для
   Colorit на том же аккаунте, скорее всего действует и здесь, но не
   проверялось).
3. Сделать одну тестовую покупку каждого товара через кнопку «Тестовый» в
   кабинете платежей и сверить фактически списанную сумму с целевыми 150₽/100₽
   — при расхождении поправить `price` в `ops/vk-payments/server.js` (голоса)
   и передеплоить (см. `ops/README.md`).
4. Реальный прогон внутри VK (не то же самое, что curl с поддельной
   подписью) — открыть Mini App в VK, убедиться, что реклама показывается,
   что валюта/чертежи/ачивки переживают перезаход, что кнопки покупки
   реально открывают VK-форму оплаты.

## Известный риск / долг

- `ops/Caddyfile` теперь одновременно "принадлежит" двум репозиториям (этому
  и `../flowit`), потому что на сервере это один общий файл для обоих игр.
  Копия в `../flowit/ops/Caddyfile` **не обновлена** этой сессией (не входило
  в задачу трогать чужой репозиторий) — при следующем изменении
  Caddyfile с любой стороны свериться с тем, что реально на сервере
  (`ssh server-games cat /opt/games/Caddyfile`), а не с одной из двух копий.
