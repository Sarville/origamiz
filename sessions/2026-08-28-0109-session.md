## Real gotcha found (worth reading before touching `res/ui/**` again)

`REBRANDING_PLAN.md` §6 says `res/ui/**` is direct file replacement with no
rebuild needed. **That's true for most of the 185-file inventory but false
for `building_icons`:** `src/css/resources.scss` calls a `uiResource()` →
`inline()` Sass function per building, and `gulp/css.js`'s `postcss-assets`
plugin base64-embeds the PNG bytes directly into compiled CSS at build time.
The running `gulp --cwd gulp` dev server's watcher only recompiles CSS when
a `.scss` file changes (`gulp.watch("../src/css/**", css.dev)`) — it has no
dependency edge from an `inline()`-referenced PNG to a CSS rebuild, so
copying the icon files alone leaves the *old* bytes baked into `main.css`
indefinitely, even though the intermediate `build/res/ui/*.png` copy does
update correctly via a separate watcher
(`gulp.watch(imageResourcesGlobs, imgres.copyImageResources)`).

**Fix used:** `touch src/css/resources.scss` to nudge the existing
`css.dev` watcher — confirmed correct by extracting the base64 blob back out
of `build/main.css` and diffing it byte-for-byte against the source PNG.

**Time sink / red herring:** the `@load-async` comment above the
building-icon rule looks like it should route the rule into
`async-resources.css` (split out by `postcss-critical-split`), which led to
a long detour suspecting a caching bug in `postcss-assets`/Sass (built an
isolated postcss-assets test, a manual pipeline reconstruction script, even
inspected `assets`/`postcss-critical-split` source for a cache). The rule
was never in `async-resources.css` in the first place — the comment sits one
selector level too deep (inside the nested `.icon` block, not on the
`[data-icon=...]` rule itself), so `postcss-critical-split` doesn't detect
it and it lands in the "rest" output, i.e. plain `main.css`. Not a bug
anywhere, just a wrong initial assumption about which file to inspect.

**Rule for next time:** before copying any `res/ui/**` file, grep
`src/css/*.scss` for `uiResource(` (or check `resources.scss`'s
`$buildings`/`$buildingsAndVariants` lists) — if the filename is referenced
there, a `.scss` touch (or `npx gulp --cwd gulp css.dev`) is required after
the copy. Files not referenced from `.scss` — most of the plan's §6.2
inventory (general UI icons, language flags, tutorial images, misc
overlays) — really are plain static copies with no rebuild step.
