# Session summary — 2026-09-01 (Chunk 2c / item 9 debt: desktop belt drag)

Continuation of the long-running chunked session on **item 9 (mobile belt
auto-tunnel/routing)**. This session tackled the first of three outstanding
debts consolidated at the end of the previous session (2026-08-31):
desktop's belt drag had no auto-tunnel support at all.

## What shipped this session

**Extracted `BeltPathPlanner`** (`src/js/game/hud/parts/belt_path_planner.js`,
new file) out of `mobile_controls.js` - the entire auto-tunnel/routing engine
(`findBeltPath`, `findBeltPathSearch`, `findBeltPathToward`, `placePath`, and
every helper: `isTileBlockedForBelt`, `pickTunnelTier`,
`buildingAcceptorFeeds`/`buildingEjectorLaunch`, `curvedEntry`,
`beltTilesToEntries`, etc.) moved line-for-line, with two deliberate seams so
the class carries no assumption about which HUD part drives it:
- `lastBeltTile`/`lastBeltIncomingDirection` (mobile's tap-continuation state,
  item 8) are no longer read off `this` - they're optional
  `continuationTile`/`continuationIncoming` parameters the caller threads
  through. Mobile's own `findBeltPathToward` became a thin wrapper that
  forwards its state; desktop always omits them (no continuation concept).
- `placePath` no longer mutates a `lastBeltTile` field - it's stateless,
  returns `{ placed, lastTile, lastIncoming }`, and takes an optional
  `continuationBefore` purely to fill undo/redo transaction meta for a
  caller that wants it.

`mobile_controls.js` shrank by ~800 lines with this extraction and now only
owns touch-gesture handling, the tap-continuation feature, and rendering.

**Wired the planner into desktop** (`building_placer_logic.js` +
`building_placer.js`): desktop's belt drag was previously the same
real-time immediate-Bresenham-placement loop shared by every building (no
"resolve the whole path, commit on release" point to hook `findBeltPath`
into). Added `beltDragStartTile`/`beltDragPath`/`beltDragPreviewEntries`/
`beltDragPreviewInvalid` state and an `isBeltSelected` getter to
`building_placer_logic.js`. `onMouseDown`'s existing immediate placement of
the anchor tile is unchanged for every building including belts - only
`onMouseMove` branches: for a belt drag specifically it now calls
`beltPathPlanner.findBeltPathToward` live instead of the Bresenham loop,
and `onMouseUp` commits the previewed path via `beltPathPlanner.placePath`
(or flashes red via a new `flashInvalidBelt`) as one transaction. Every
other building's placement is untouched. `building_placer.js` gained the
matching draw-side pieces ported from mobile
(`drawBeltDragPreview`/`drawRedTiles`/`drawInvalidBeltFlash`/
`drawPreviewEntry`/`tunnelFakeEntity`).

TODO.md updated: the desktop debt bullet in the consolidated list is struck
through as resolved, and a detailed "seventeenth follow-up" write-up was
added (matching the project's established documentation density for this
