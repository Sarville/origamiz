## Part 1 — 2c-9 parity fixes (5 items, see TODO.md for full detail)

1. **Mobile layers toggle** - new idle-row icon (hand-drawn stacked-rhombus
   glyph), hidden via `[hidden]` until the wires reward unlocks. Calls the
   existing `HUDWiresOverlay.switchLayers()`.
2. **Desktop undo/redo, Ctrl+Z/Ctrl+X.** Root-cause fix: desktop placements/
   deletions were never wrapped in an `actionHistory` transaction at all
   (only mass-select/blueprint-paste/belt-path-planner were) - undo would
   have silently done nothing. Fixed by wrapping `tryPlaceCurrentBuildingAt`
   and the two raw `tryDeleteBuilding` call sites. New keybindings collide at
   the raw keyCode level with `copyWireValue` (Z) and `massSelectCut` (X) -
   both now bail early when Ctrl is held.
3. **Mobile pipette.** New `HUDBuildingPlacerLogic.pipetteAt(tile)`,
   refactored out of `startPipette` so mobile shares the same logic. New
   idle-row eyedropper icon.
4. **Desktop transform/move, "T".** New `startTransform()`, mirrors mobile's
   `beginMoveExistingBuilding`; reuses the ordinary placement flow (left
   click confirms, "R" rotates). `abortPlacement()` now restores the
   picked-up original via undo when cancelled; a confirmed move calls
   `combineLastTwo()` so one undo goes straight back.
5. **Desktop belt continuation across zoom.** `lastBeltTile` was only ever
   written by the overview-zoom code path - normal-zoom clicks/drags never
   updated it, so zooming out always started a fresh segment. Fixed at both
   normal-zoom write sites (anchor tile in `onMouseDown`, drag commit in
   `onMouseUp`).

All five verified live via Playwright against the dev server (desktop +
mobile touch emulation) - undo/redo round-tripped a belt placement exactly,
"T" picked up/moved/cancelled a building with no duplicates, a belt built
half at normal zoom and half at overview zoom came back as one connected
run.

## Part 2 — Main menu / dialogs / mobile icon redesign

User supplied real-device reference screenshots and, later, exact CSS files
(`origamiz-main-menu-buttons.css`, `origamiz-modal-windows.css`) to match
"one-to-one".

- **Main menu** (`main_menu.js`/`.scss`): Continue/New Game/Play are now
  card-style buttons (warm cream / orange gradients, folded-paper corner,
  play-triangle icon) instead of the old flat green button; Continue shows
  the latest savegame's level as a subtitle; savegame rows' resume button
  got the same treatment. Also removed (per an earlier request in the same
  thread): the language-flag icon, changelog/help-translate footer links,
  Puzzle DLC card, Import and Mods buttons - `mainWrapper`'s `data-columns`
  is now `hasMods ? 2 : 1` and the small-button `.outer` div is only
  appended when non-empty, so nothing leaves a dead grid column behind.
- **Cross-device sizing bug, found via the user's own phone screenshots**:
  card text was clipping/overlapping on their real device despite fitting
  in every desktop/emulated test. Root cause - this project's `1rem` is a
  *dynamic* UI-scale value (`Application.checkResize`), not the browser's
  fixed 16px, and mixing that with `vw` (viewport-relative) produced
  different actual proportions per device. Fixed by switching the card
  buttons to `container-type: inline-size` + `cqw` (container query width)
  for font-size, and `aspect-ratio: 2.3/1` instead of a flat rem
  min-height - both now track the button's own rendered box directly,
  independent of viewport or UI-scale. Verified by screenshotting at 4
  different CSS widths (360/393/412/480px) - proportions held at all four
  where the old rem/vw mix hadn't.
- **Folded-corner iterations** (multiple rounds of user feedback): first
  pass was a thin diagonal stripe, not a real fold. Rebuilt as two
  triangles sharing one box - a shadow strip along the crease (`::before`)
  and the flap itself, same color family as the card face, pointing inward
  with its own `drop-shadow` (`::after`). First version of the crease
  shadow had a geometry bug - a 135deg gradient's stop percentages were
  measured from the box's *corner* (0%), but the crease line on a square
  box actually sits at *50%* along that axis, so the "0%-18% fade" band
  was entirely outside the visible notch triangle and invisible. Recentered
  the stops on 50%, strengthened opacity, and left a light persistent shade
  in the corner past the crease per the user's last request ("shadow along
  the whole fold + slightly shade the corner under it").
- **Dialogs** (`dialogs.scss`): ported the user's modal CSS onto the
  *existing* shared `Dialog` class (`.ingameDialog > .dialogInner`, used by
  every dialog in the game via `showWarning`/`showInfo`/`DialogWithForm`) -
  one change point covers all ~13 call sites automatically. Warm paper
  gradient panel, folded-corner accent, chunky sage/coral gradient buttons
  for `.good`/`.bad` (was flat `$colorGreenBright`/`$colorRedBright`). The
  "!" warning icon and dividers key off the existing `type: "warning"`
  class so they only show on `showWarning()` dialogs (delete confirms etc.),
  not `DialogWithForm` (rename) - matches the reference exactly with no
  extra JS. Savegame delete confirmation got a `.saveInfo` card
  (filename+level) and a red-dot `.warningNote` line, built directly into
  `MainMenuState.deleteGame()`'s content HTML. Dark-theme variants for all
  new colors. Caught one real authoring bug before it shipped: my first
  edit to `translations/base-en.yaml` for the new `preload:` keys landed
  the block *inside* `global:` by mistake (same indentation as `global`'s
  later keys, silently re-parenting them) - caught via
  `python3 -c "import yaml; ..."` round-tripping both translation files,
  not just eyeballing the diff.
- **Mobile HUD icon size**: showed the user 3 side-by-side size options
  (52%/65%/80% `background-size`) on the trash icon as an example; they
  picked 80%, applied to all 15 icon `background-size` declarations in
  `mobile_controls.scss` for consistency.
- **Final two small corrections from the user**: reverted the savegame
  row's "X hours ago" font-size bump (kept the level bump, which they did
  want) back to the original `SuperSmallText`; fixed the crease-shadow
  gradient-stop bug above.
