# Session: Currency Shop + Shape Exchange system

Continued from a prior (context-compacted) session. This session finished and
polished the in-game currency/shop monetization system for the Yandex Games
port ("origamiz" rebrand).

## Summary

Built a full Shop + Shape Exchange feature on top of the existing
`storedShapes` shape-delivery bookkeeping (`hub_goals.js`), using a fixed
shape code (`CgCgCgCg:RwCu--Wu:----Rw--`) as in-game currency:

- **Shop window** (`currency_shop.js`, unlocked at level 9 alongside
  Research Tier 1): daily free-currency claim, and five one-off toggle
  purchases (auto-tunnel, long-distance belt routing, build-while-zoomed-out,
  auto-merger, auto-splitter) each gated behind `enumHubGoalRewards` reward
  flags and a currency price (in the low thousands).
- **Shape Exchange** (`shape_exchange_list.js` + `shape_exchange_modal.js` +
  `shape_exchange_rates.js`): buy/sell any owned shape for currency at a
  rate driven by layer count + painted/plain, via a small amount-entry modal
  (stepper, MAX button, round-to-valid-step warning, backend-revalidated
  purchase). Exchange itself is a purchasable feature (5k) with a daily
  operation limit (3, raisable +3 up to 3 times for 5k each).
- **Savegame migration**: bumped to version 1012, real `migrate()` steps for
  both `dailyBonusClaimedAt` (1010→1011) and the three new Exchange-limit
  fields (1011→1012) so existing saves load without a hard schema error.
- **Belt auto-merger/splitter**: extended `belt_path_planner.js` so dragging
  a belt into an existing perpendicular belt run (a genuine mid-trunk
  continuation, not the tail) auto-inserts a merger/splitter instead of
  overwriting it - gated behind the Shop purchase.
- **UI polish this session**: shop item price moved to its own column next
  to the Buy button (no more overlap on short cards); buy/sell amount input
  no longer prefilled (placeholder instead); exchange rate formula reworked
  to depend on layer count + paint; added a "Rates" reference table modal;
  daily Exchange operation limit + its own purchasable-feature gate and
  raise-limit purchase; amount-input stepper height fixed to match the
  input exactly (flex `min-height: 0` fix - default `min-height: auto` on
  flex items let the input's Heading-sized text overflow past the row's
  declared height at some UI scales); added a MAX button; close ("×")
  button repositioned to the dialog's true top-right corner for every
  dialog (shared `dialogs.scss` base rule) with more top padding to clear
  it; fixed a leaking `margin-top: 1.2rem` from the generic
  `.dialogInner .content input` rule (meant for rename/marker-style
  dialogs) that was pushing the amount input out of alignment with its
  stepper/MAX button.
