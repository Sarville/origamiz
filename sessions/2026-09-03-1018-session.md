## What shipped

- `tutorial_goals.js` / `tutorial_goals_mappings.js` — two new rewards,
  `reward_research` and `reward_research_t2` (map to `null` content, same as
  `reward_blueprints`/`reward_freeplay` — they just gate the UI, not a
  building).
- `modes/levels.js` — the 8 rewards that used to unlock building variants on
  level-up (levels 7, 9, 11, 13, 16, 17, 18, 19) are removed from the level
  ladder. Level 9 now grants `reward_research` (opens Tier 1), level 16
  grants `reward_research_t2` (opens Tier 2); the other 6 freed levels grant
  `no_reward`.
- `modes/regular.js` — `generateResearch()` / `getResearch()`: a static
  table of the 8 research entries (`{ tier, reward, required: [{shape,
  amount}] }`). Currency per tier reuses the shape of the level that opens
  it (no new shapes introduced, mirrors the legacy mod's design in
  §B.1/§B.4); the "own" shape per variant reuses whatever shape used to sit
  on its old level-ladder slot. One edge case: Balancer Merger's own shape
  and the Tier-1 currency shape are literally the same shape (both were
  level 9's), so its `required` folds into one entry instead of listing the
  same shape twice.
- `game_mode.js` — default `getResearch() { return {}; }` for other game
  modes, following the existing `getUpgrades()`/`getLevelDefinitions()`
  pattern.
- `root.js` — new `researchPurchased` signal (parallels `upgradePurchased`).
- `hub_goals.js` — `canUnlockResearch` / `tryUnlockResearch` /
  `isResearchCompleted` / `isResearchTierUnlocked`, plus
  `RESEARCH_TIER_UNLOCK_REWARDS` (tier → gating reward). Purchasing a
  research entry just adds its `reward` to the *existing* `gainedRewards`
  Set — every building-availability check in the codebase
  (`rotator.js`, `cutter.js`, `balancer.js`, `miner.js`, `painter.js`,
  `underground_belt.js`, …) already reads `isRewardUnlocked(reward_X)` for
  these exact 8 rewards, so nothing else needed to change for the purchased
  variant to become placeable. No savegame schema change either —
  `gainedRewards` was already `types.set(types.string)`.
- `hud/parts/shop.js` + `src/css/ingame_hud/shop.scss` — a "Research"
  section appended inside the same Upgrades dialog, hidden entirely until
  Tier 1 unlocks. Cards reuse the existing `.upgrade` card markup/CSS
  (title, tier badge — reuses the tier-color palette by tier-1, requirement
  progress bars, buy button) so no new visual language was invented. Unlike
  upgrades, research requirements are static (one purchase, not tiered), so
  they're built once in `createElements()` instead of being rebuilt on every
  `rerenderFull()`; extracted the requirement-DOM-building code (shape
  canvas + progress bar + pin/info buttons) out of `rerenderFull()` into a
  shared `createRequirementElement()` used by both upgrades and research to
  avoid duplicating ~90 lines. New card states: `.completed` (green,
  reuses `.maxLevel`'s hide-requirements/hide-button styling) and `.locked`
  (dimmed, tier-gated, shows "Locked (Research Tier N required)").
- `translations/base-en.yaml` + `base-ru.yaml` — `storyRewards.reward_research`
  / `reward_research_t2` (title+desc, shown by the existing level-up popup);
  `ingame.shop.researchSectionTitle` / `buttonResearch` / `researchLocked` /
  `researchCompleted`. Card titles reuse the existing per-variant
  `storyRewards[reward].title` strings — no new per-variant translation
  needed.
