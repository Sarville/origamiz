# Session 2026-09-07 13:20 — Belt autopath as a Shop purchase + split tutorial hint

## Why

User reported (screenshot, level 1 tutorial): the green "hold and drag"
hint shows one continuous bent path (extractor → up → right → hub), but
the belt auto-router (`BeltPathPlanner`, item 9) can legally resolve the
drag to a *different* bend and land somewhere that doesn't match the
hint — confusing for a brand-new player. Requested fix, in four parts:

1. Belt auto-routing (bends, obstacle-crossing, tap-continuation) becomes a
   paid Shop purchase ("Автопуть", 1000 currency) instead of being on by
   default. Before it's bought: belt dragging is straight-line only, and a
   plain tap/click always places a single tile instead of continuing the
   previous run.
2. The green tutorial hint for level 1's "connect extractor to hub" step
   splits into two sequential single-segment hints (up, then right) instead
   of showing the whole bent path at once, so it always matches what a
   straight-only drag can actually produce.
3. Shop item cards show immediately (with their price) from level 1 instead
   of being hidden behind the whole Shop's own level-9 unlock — only the
   Buy button itself waits for level 9.
4. Shop item order: Автопуть, Дальняя прокладка, Чертежи, Автотуннели, then
   the rest unchanged.

Follow-up in the same session (from a second user question): longRoute/
autoTunnel/autoMerger/autoSplitter only ever take effect *inside*
`BeltPathPlanner.findBeltPathSearch`, which itself is now gated behind
autoPath — so those four were purchasable-but-inert without autoPath first.
Added a `requires` prerequisite chain so they can't be bought before
autoPath. Per user follow-up: the prerequisite message ("Требуется:
Автопуть") replaces the *Buy button's label*, not the price — the price
still always shows the real number.

## Yandex bundle rebuild (this session, after commit)

Per the prior session's note (`sessions/2026-09-05-0900-session.md`): the
dev server was **stopped** before running `npm run build-yandex`, since
both build variants (`web`/`yandex`) write to the same `build/` folder and
racing the dev server's own watch-rebuild against a full `build.yandex.full`
run would corrupt it. Output zipped flat (no wrapping directory — index.html
at zip root, which is what Yandex Games' upload expects) into
`yandex-bundle.zip` at the repo root, overwriting the previous one from
2026-09-05. `yandex-build.zip`/`origamiz-yandex-1.6.0.zip` are older,
untracked leftovers — left alone as before.
