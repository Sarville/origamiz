- **2026-08-27 (real outline bug this time, self-inflicted).** Immediately
  after the JPEG-ringing false alarm, user sent one more crop that WAS a
  real defect: broken/branching dark outline at concave corners (chimney-
  to-body junction) on several files. Root cause: my own `ImageFilter.
  MaxFilter`-based outline dilation used a SQUARE kernel, which doesn't
  close cleanly at concave silhouette corners. Fix attempt #1 (erode the
  combined mask by the same square kernel to recover "pre-outline" art,
  then redraw with a disk-kernel dilation + closing) worked visually but
  **regressed tab centering** on 5 files (`logic_gate`, `transistor`,
  `transistor-mirrored`, `virtual_processor-stacker`,
  `virtual_processor-painter`) back toward their pre-PROMPT26/27 offsets —
  square erosion behaves asymmetrically right at a canvas-edge tab, since
  there's no room to erode from the "outside" (the canvas boundary itself).
  Fix attempt #2 (correct, shipped): a NON-destructive version for the
  other 11 files — `scipy.ndimage.binary_closing` with a disk structuring
  element applied directly to the CURRENT (art+old outline) mask, filling
  only small gaps, never eroding anything that already existed, so tab
  geometry can't shift. For the 5 regressed files, a fresh codex pass
  (`PROMPT27_recenter_and_outline.md`, output in `staging_wire_v5/`) with
  exact per-file pixel-offset targets (same technique as PROMPT26), which
  itself left two small new artifacts caught by re-measuring rather than
  trusting its self-report: every one of the 5 files was missing exactly
  the outermost 1px on some edges (row/col 0 or 191 fully transparent

  outward), and `transistor.png` had a 49px outline fragment fully
  disconnected from the main shape (found via

  step: never erode a mask that includes edge-touching tabs (canvas
  boundary breaks the math); only ever grow/close; and after any
  regeneration, verify with connected-components + per-edge presence
