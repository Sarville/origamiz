# Сессия 2026-08-24 22:38 — Yandex Games порт, кусок 1/3: браузерный платформенный рантайм

## Контекст задачи

Цель: перевести shapez CE (сейчас Electron-only) на web/WebGL-hosting для Yandex Games.
Разведка (см. обсуждение в чате, не задокументирована отдельным файлом):

- Реальная точка расхождения CE от `tobspr-games/shapez.io` — декабрь 2022 (commit `0713c850`), а не ноябрь 2023, как можно было бы подумать по README. С этой точки у CE 232 коммита реальной разработки, у оригинала — 4 косметических коммита в README. Оригинал де-факто заморожен, использовать его как базу не стоит.
- У оригинала (`tobspr-games/shapez.io`, ветка HEAD на момент проверки: `ae88eb48`) всё ещё жива браузерная платформа: `src/js/platform/browser/{wrapper.js,storage.js,storage_indexed_db.js,sound.js}` и multi-variant gulp-сборка (`web-localhost`, `web-shapezio-beta`, `web-shapezio`), плюс прецедент интеграции стороннего игрового портала (CrazyGames SDK). Использовался как референс архитектуры (не скопирован дословно — текущая архитектура `Storage`/`wrapper.js` в CE с тех пор изменилась, TS-миграция и др.).
- CE выпилила веб-поддержку осознанно (README: "no plans for re-supporting a web version"), вся игра сейчас жёстко завязана на Electron через глобальный `ipcRenderer` (инжектится `electron/preload.cjs` через `contextBridge`).

Общий план на 3 куска (независимые, каждый — отдельная сессия):
1. **Платформенный рантайм** — игра грузится и играбельна в обычном браузере без Electron. ✅ этот кусок.
2. **Сборка** — отдельный `web`-вариант в gulp (сейчас в `gulp/build_variants.js` только `standalone`), продакшн-бандл без Electron-обёртки.
3. **Yandex Games SDK** — `ysdk.features.LoadingAPI.ready()`, реклама, HTML-шаблон с `<script src="https://yandex.ru/games/sdk/v2">`.

## Что сделано в этой сессии (кусок 1)

Ключевая находка перед началом работы: вся файловая I/O игры проходит через **один** класс `Storage` (`src/js/platform/storage.ts` → `invokeFsJob`), а вся платформенная специфика — через **один** класс `PlatformWrapperImpl*` (`src/js/platform/wrapper.js`). Это сильно упростило порт: не нужно было трогать десятки файлов.

Изменённые/новые файлы:

- **`src/js/platform/browser_fs_job.ts`** (новый) — браузерная реализация контракта `fs-job` (зеркалит `electron/src/fsjob.ts`), на IndexedDB (`shapez_fs` / store `files`, ключ `${storageId}/${filename}`). `open-external`/`save-external` — через нативный `<input type=file>` и Blob+`<a download>`, без сторонних библиотек. Ошибка "файл не найден" намеренно формируется в том же строковом формате, что и реальная Electron IPC-ошибка (`Error invoking remote method 'fs-job': Error: ENOENT: ...`), потому что `FsError` (`platform/fs_error.ts`) парсит код ошибки через `message.split(":")[2]` — трогать этот парсер не стал, чтобы не расширять диф.
- **`src/js/platform/storage.ts`** — `invokeFsJob` теперь branch: `typeof ipcRenderer !== "undefined"` → Electron IPC, иначе → `handleBrowserFsJob`.
- **`src/js/platform/wrapper.js`** — добавлен `PlatformWrapperImplBrowser` рядом с существующим `PlatformWrapperImplElectron` (не абстрагировал в общий базовый класс — методы почти идентичны, но код небольшой, дублирование дешевле новой абстракции). Отличия от Electron-версии: `getId()` → `"browser"`, `openExternalLink` → `window.open`, `setFullscreen`/`getSupportsFullscreen` → нативный Fullscreen API вместо `ipcRenderer.invoke("set-fullscreen")`, `exitApp`/`getSupportsAppExit` → no-op/false (в браузере нельзя закрыть вкладку кодом).
- **`src/js/application.js`** — выбор класса враппера по `typeof ipcRenderer !== "undefined"` вместо жёсткого `new PlatformWrapperImplElectron(this)`.
- **`src/js/mods/modloader.ts`** — `initMods()` больше не падает без Electron: без `ipcRenderer` возвращает пустой список модов вместо `await ipcRenderer.invoke(...)` (упало бы с `ReferenceError`). Моды в web-сборке сознательно отключены — они завязаны на `mod://` протокол и локальную ФС, для Yandex Games не нужны и не имеют смысла.

### Найденный и исправленный попутный баг

При первом прогоне в браузере поймал `TypeError: Permissions check failed` (Unhandled Promise rejection) при старте. Причина — НЕ моя правка: `src/js/states/preload.js:70` на каждом старте безусловно вызывает `platformWrapper.setFullscreen(settings.getIsFullScreen())`, восстанавливая сохранённую настройку полноэкранного режима. В Electron это безобидно (IPC-сообщение окну ОС), но настоящий Fullscreen API браузера требует user gesture (клика) и синхронно/асинхронно реджектит промис при вызове на старте без клика — в реальных браузерах это будет ронять игру точно так же, не только в тестовой headless-среде. Исправлено в `PlatformWrapperImplBrowser.setFullscreen`: промисы `requestFullscreen()`/`exitFullscreen()` теперь глушатся (`.catch(() => {})`), это ожидаемое и безопасное поведение, а не баг, который стоит пытаться "чинить" иначе.

Сохранения идут через IndexedDB (`app_settings.bin` записался и прочитался в логах консоли).
  - Важно: чистый `headless` chrome (`--headless --screenshot=...`) для этой проверки **не подходит** — headless Chrome репортит `document.hidden = true`, и игра сама паузит рендер/боот-прогресс ("Application renderable: false" в консоли), что выглядит как зависание, но им не является. Для визуальной проверки нужен реальный X-дисплей (Xvfb + не-headless chrome + `import -window` для скриншота), не `--headless`.

## Известные ограничения / не сделано в этом куске

- Файл `open-external`/`save-external` в `browser_fs_job.ts` не резолвит промис при отмене диалога выбора файла в старых браузерах — используется нативное событие `"cancel"` на `<input type=file>` (Chrome 113+/Firefox 106+), для более старых браузеров промис просто зависнет. Помечено `ponytail:`-комментарием в коде. Не критично для Yandex Games (там актуальный Chromium через встроенный webview).
- Мод-система (`ModLoader`) в браузере отдаёт пустой список — это осознанное решение, не баг. Если Yandex-версии когда-нибудь понадобятся моды, это отдельная задача (потребует своего транспорта вместо `mod://` протокола).
- IndexedDB-хранилище пока без обработки квоты/эвикции (браузер может подчистить IndexedDB при нехватке места на "непостоянных" источниках) — для MVP не критично, но стоит держать в голове при полноценном тестировании на реальных пользователях Yandex Games.
