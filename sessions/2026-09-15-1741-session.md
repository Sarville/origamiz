# Сессия 2026-09-15 17:41 — платежи ОК (Одноклассники) поверх VK Mini App

## Что просили

Реализовать поддержку платежей ОК (ОК интегрировала платформу VK Mini Apps,
это тот же VK Mini App, не отдельная платформа) по `docs/vk-ok-payments-findings.md`
(находки из добавления ОК-платежей в `../../flowit`/Colorit). Цены:
отключение рекламы — 20 голосов ВК / 100 ОКов; пак валюты — 10 голосов ВК /
50 ОКов.

## Что сделано

### Сервер (`ops/vk-payments/server.js`)

- `ITEMS`: у `disable_ads`/`currency_pack_10k` теперь два поля цены — `price`
  (VK «голоса»: 20 / 10) и `priceOk` (OK «ОКи»: 100 / 50). Раньше был только
  `price`, причём в рублях-как-голосах (150/100) — по находкам из
  `vk-ok-payments-findings.md` это была вероятная 10-кратная переплата
  (1 голос ≠ 1 рубль), сейчас цены заданы прямо в целевой валюте каждой
  платформы.
- `get_item` теперь отвечает `item.priceOk`, если `params.site === "ok"` —
  один и тот же классический POST-канал обслуживает оба клиента (VK и OK),
  только цена в ответе разная.
- Новая функция `handleOkPaymentNotification` + маршрут
  `GET /vk/origamiz-payments/ok` — отдельное подтверждение покупки ОК
  (`apiok.ru callbacks.payment`, тот же `APP_SECRET`/формула подписи, что и
  классический канал, но GET-запрос и другой формат ответа: `true` на
  успех, `{error_code,...}` + заголовок `Invocation-error` на ошибку).
  Начисляет тот же ledger (`adsDisabled`/`pendingCurrencyPacks`), что и
  `order_status_change` — это единственное место, где реально подтверждается
  ОК-покупка (по докам, классический `order_status_change` для ОК не
  срабатывает, только для VK).
- `isAcceptableReferer`: добавлен `ok.ru`/`*.ok.ru` в allowlist (был только
  `vk.com`/`vk.ru`) — иначе мягкая проверка реферера при входе на
  `/vk/origamiz` могла бы **заблокировать** реальных игроков из ОК, если их
  iframe шлёт `Referer: ok.ru` (это не подтверждено реальным запуском —
  см. «Не проверено» ниже).
- Экспортирован `handleOkPaymentNotification` для тестов.

### Тесты (`ops/vk-payments/server.test.js`)

Добавлены проверки `handleOkPaymentNotification`: валидное подтверждение
(`true` + начисление в ledger), подделанная подпись (`Invocation-error: 1001`),
несовпадение цены с `priceOk` (`error_code: 1001`). Прогнано —
`node ops/vk-payments/server.test.js` зелёный.

### Инфраструктура (`ops/Caddyfile`)

Маршрут `handle /vk/origamiz-payments` заменён на именованный matcher
`@origamizPayments path /vk/origamiz-payments /vk/origamiz-payments/ok` —
Caddy `handle` матчит путь точно, без префиксов, поэтому без этого
`/vk/origamiz-payments/ok` отвечал бы 404 через основной `file_server`.
Тот же паттерн, что уже использован в `flowit/ops/Caddyfile` для Colorit.

### Документация

  ссылка на findings-доку), добавлен новый раздел «OK (Odnoklassniki)

## URL для кабинета dev.vk.ru

`https://games.sarville.online/vk/origamiz-payments/ok` — «URL для
платёжных уведомлений Одноклассников» (отдельное поле, не путать с
классическим `https://games.sarville.online/vk/origamiz-payments`).

## SDK/авторизация/синхронизация для ОК — без изменений

Проверено по `src/js/platform/vk_wrapper.js`: тот же `@vkontakte/vk-bridge`
(`VKWebAppInit`), та же launch-params подпись (`isValidLaunchParams`
подписывает все `vk_`-параметры динамически, включая добавляемый ОК
`vk_client=ok`), то же облачное хранилище (`VKWebAppStorageGet/Set`), тот же
`VKWebAppShowOrderBox` для покупок. Клиентских правок не потребовалось —
только серверная часть (платежи) и Caddy-роутинг.

## Не проверено (риски перед публикацией)

Оба пункта унаследованы из `docs/vk-ok-payments-findings.md` и подтверждены
поиском (WebSearch/WebFetch по apiok.ru — точный Referer/домен iframe ОК не
нашёлся в открытой документации):

1. **ОК-подтверждение платежа** (`handleOkPaymentNotification`) не
   проверялось на реальном захваченном запросе от ОК — собрано по докам
   (dev.vk.ru + apiok.ru). Нужно прогнать «Тестовый» пробник в кабинете ОК
   и сверить точные имена/регистр параметров, а также формат ответа (JSON
   vs XML — в кабинете есть настройка «Версия API»).
2. **Referer при реальном запуске из ОК** — добавлен `ok.ru` в allowlist
   defensively, без подтверждения. Если реальный iframe шлёт другой домен,
   гейт `/vk/origamiz` будет 403-ить настоящих игроков из ОК. Проверить
   реальным запуском перед публикацией.
